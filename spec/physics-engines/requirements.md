# Requirements

Status: approved by the owner on 2026-10-25. These requirements describe proposed behavior, not available service features.

## Scope

All three backends are required deliverables. The first implementation increment is `lindblad`, backed by QuTiP. It supports coupled oscillators, Duffing modes and explicit finite matrices; evolution, static spectra, propagators and steady states. The next increments implement scqubits circuit spectra/operator export and restricted JoSIM transient simulation within this same approved scope. GPU feasibility and measured acceleration are included. Palace, persistent quantum state, job dependencies and workflow orchestration are excluded.

## Observable requirements

- **PHY-001 — Existing clients.** The service shall preserve existing circuit routes, default engines, accepted inputs, error behavior, idempotency reservations, polling, SSE resume, cancellation, cleanup and deletion. Existing `engines` capability metadata shall remain an object keyed by engine name.
- **PHY-002 — One job system.** New requests shall use the existing authenticated, owner-scoped durable queue, dispatcher, SkyPilot workers, callback authentication and NPZ storage. There shall be no new scheduler, session store or stateful simulation service.
- **PHY-003 — Submission.** The service shall accept versioned declarative JSON at `POST /api/jobs/lindblad` and the general jobs route using `engine=lindblad`, `input_format=lindblad_model`, and `schema_version=1`. The explicit route shall require the existing Idempotency-Key header. The general route shall retain its existing optional-header behavior. Equivalent submissions through either route shall normalize to the same request identity.
- **PHY-004 — Input boundary.** Unknown fields, nonfinite numbers, invalid references/shapes, out-of-range indices, incompatible operations/solvers and over-budget requests shall be rejected before queueing. New physics validation errors shall carry a JSON Pointer. Existing circuit error envelopes shall not change. The existing HTTP request-byte limit remains authoritative.
- **PHY-005 — No caller code.** The service shall accept no Python, symbolic expressions, serialized executable objects, user file paths or arbitrary library options. QuTiP time-dependent coefficients shall use numeric arrays with explicit interpolation. scqubits constructors/operators shall use class-specific allowlists; JoSIM shall use a positive allowlist of supported statements and reject filesystem access, including nested directives.
- **PHY-006 — Units.** Mode Hamiltonians, static coefficients and drive amplitudes shall use linear GHz, converted to angular units by multiplying by 2π exactly once. Lindblad time shall use ns and collapse rates 1/ns. Lindblad/scqubits spectrum outputs shall return linear GHz; JoSIM retains its native SI units. The service shall never infer or change a rotating frame.
- **PHY-007 — Models.** Ordered modes shall define tensor order. Operators shall be restricted to documented ladder/number/quadrature/identity/projector primitives and named matrices. The service shall validate unique mode/operator names, explicit matrix dimensions, Hermiticity where required and nonnegative decay rates. `hc=true` shall add the full conjugate term, including the conjugated coefficient.
- **PHY-008 — State.** Models shall accept normalized nonzero pure amplitudes, product Fock/coherent states, and documented density/thermal states. Pure-state solvers shall reject mixed-state inputs. Density matrices shall be Hermitian, trace-one and positive semidefinite within published numerical tolerances. Missing product modes shall start in vacuum. Invalid physical states shall never be silently repaired beyond documented pure-state normalization.
- **PHY-009 — Evolution.** `evolve` shall expose Schrödinger (`se`), master-equation (`me`) and Monte Carlo (`mc`) solvers with explicit increasing output times and named observables. `se` shall reject dissipation. `mc` shall use a bounded trajectory count and deterministic seed mapping. Results shall identify solver, units, tensor order, representation and array shapes.
- **PHY-010 — Other operations.** `spectrum` shall diagonalize the static Hamiltonian and return sorted eigenvalues, with optional eigenvectors. `steadystate` shall use the static Lindbladian and reject drives. `propagator` shall return a unitary (`se`) or superoperator (`me`), never mislabel one as the other. Unsupported combinations shall be rejected rather than approximated.
- **PHY-011 — Resources.** Admission shall bound tensor dimension, density/Liouville dimension, coefficient samples, matrix elements, trajectory count, retained solver states and final output bytes. The existing 2 CPU/4 GiB worker profile is a baseline, not a requirement to run CPU-only. GPU placement may be selected by a reviewed server policy when native support, correctness and measured benefit are established. Limits shall be supported by constrained worker measurements; a dimension cap alone is not sufficient memory evidence. No new global job-count cap or simulation wall-time cap is introduced.
- **PHY-012 — Results.** The result shall remain one NPZ readable with `allow_pickle=False`. Numeric arrays shall preserve complex values. A zero-dimensional Unicode `metadata_json` array shall record engine/library/schema versions, operation, units, mode ordering, dimensions and seed where used. Bounded JSON summaries shall contain shapes and statistics rather than copies of large arrays.
- **PHY-013 — Transport.** Accepted maximum results shall fit the existing callback body, base64 field and result storage limits without relying on compression. The worker shall verify the actual encoded payload before callback. An excessive result shall fail clearly without an endless callback retry or a false success.
- **PHY-014 — Discovery.** The service shall publish the structural schema used for validation at `/api/schemas/lindblad/1.json`, `/api/schemas/scqubits/1.json` and `/api/schemas/josim/1.json`, with documented semantic constraints. Capabilities shall list only implemented, tested operations and pinned library versions. The API shall not import a solver to answer capability/schema requests.
- **PHY-015 — Documentation and CI.** Developer and agent guides shall contain a validated example, units, operation/solver support, resource limits and result interpretation. Standpunkt-first CI and hosted fallback shall exercise all advertised engines, schemas, request lifecycle and mathematical correctness; deployment acceptance shall also exercise the new engine before general admission reopens.
- **PHY-016 — scqubits and JoSIM.** scqubits shall restrict native classes and constructor/operator parameters, validate dimensions before allocation, and support a tested numeric export into Lindblad. JoSIM shall require bounded explicit traces, bounded transient output, server-owned scratch/output paths and a validated physics fixture. Neither engine shall be advertised until its own implementation, version/license review and tests pass.

- **PHY-017 — scqubits API.** The service shall provide `POST /api/jobs/scqubits` and generic `input_format=scqubits_model`, schema version 1, with `spectrum`, `matrix_elements` and `export_for_lindblad`. Supported classes shall be Transmon, TunableTransmon, Fluxonium and FluxQubit, with class-specific constructor/operator allowlists. The export shall preserve a stated energy reference and basis and reproduce the selected spectrum in Lindblad.
- **PHY-018 — JoSIM API.** The service shall provide `POST /api/jobs/josim` and generic `input_format=josim_netlist`, schema version 1, with `transient`. Results shall contain SI time, selected trace values, stable trace names and units. Invalid/unsupported netlist statements shall be rejected before queueing, with no caller-selected output path. Noise options and seed behavior shall be advertised only after native support and reproducibility are verified.
- **PHY-019 — GPU discovery.** The implementation shall assess native GPU acceleration for Lindblad and scqubits, including small and large representative workloads, numerical precision, memory, cold/warm setup, data transfer and scheduling time. It shall record supported operations and backend/library/device versions. The service shall not infer acceleration from installed CUDA packages alone. JoSIM shall remain CPU-based unless a supported and tested GPU implementation is established.
- **PHY-020 — Placement and fallback.** A reviewed server-managed policy shall select an operation-compatible worker image and CPU/GPU resources through the existing SkyPilot launcher. It shall preserve queueing, cancellation, per-job isolation and reproducibility metadata. It shall define GPU-unavailable behavior explicitly and never silently change precision, solver or accepted model semantics. Clients shall not submit arbitrary resources or native backend names. Unproven GPU paths shall not be advertised as available.

## Deferred by default

Parameter sweeps remain a proposed later increment. Clients continue to manage batches, sequences and state. No new progress event or fractional solver progress is promised; existing durable SSE job progress remains available. Structured scqubits Circuit/YAML input and Palace mesh uploads are excluded.

## Acceptance examples

Lindblad must satisfy Rabi oscillation, exponential T1 decay, coherent resonator ringdown, thermal occupation, dispersive spectral shift, Monte Carlo agreement with master-equation statistics, and analytic propagator checks. Additional checks must catch non-Hermitian models, unphysical states, coefficient conjugation errors, tensor-order errors and operation-specific resource overflows. API tests must show that rejected physics inputs create no jobs and that lifecycle behavior is shared with existing circuit jobs.
