Quantum simulation on CPU

Clifft 0.11 is an exact simulator for near-Clifford circuits: circuits built mostly from efficiently simulatable Clifford gates, with additional non-Clifford operations such as T gates. It keeps the actively simulated part of the quantum state compact. Runtime and memory depend on this active width and the circuit’s structure, so qubit count alone does not tell you how difficult a simulation will be.

Google’s qsim 0.22.1 is a full state-vector simulator. It supports general unitary circuits, including circuits with many non-Clifford gates. Memory grows exponentially with the total qubit count. Our CPU service supports measurement sampling and selected basis probabilities through tested OpenQASM 2 and 3 subsets, using single-precision simulation. Try the qsim example.

Use Stim or Google qsim QASM circuits for sampling, or supported unitary QASM circuits for basis probabilities. Explore algorithm prototypes and error-correction experiments, then collect results from your own scripts. Measurement samples still have finite-shot statistical variation, even with an exact simulator.

Qiskit Aer 0.17.2 runs conditional circuits on CPUs in double precision. Use a measurement result to control a later gate, or reset and measure inside a branch. Choose Aer explicitly through the same durable job API. Try classical conditions.

With thanks to Unitary Foundation, which builds and maintains Clifft, and to its open-source contributors. Google’s qsim project ↗ is available under the Apache 2.0 license.

Your first simulation

Run simulations from your scripts and applications. Submit a circuit, watch its progress, and download samples or exact basis probabilities when the job completes.

BASE URLhttps://simulation.example.invalid

Have your API key ready. The examples below take you from a circuit to a downloaded result. Need a key? Request access.

Choose your task

For measurement samples, submit a Stim circuit or select Google qsim QASM sampling. For probabilities of selected basis strings, submit a supported unitary OpenQASM 2 or 3 circuit. Each submission runs independently; your application coordinates multiple jobs.

Quick start: sample a Bell pair

Use an invitation key. The shell examples need curl, jq, and uuidgen. Read your key into an environment variable instead of putting it in a URL.

read -rsp "wqsim API key: " QSIM_API_KEY
export QSIM_API_KEY
BASE=https://simulation.example.invalid

1. Submit

POST /api/jobs/stim returns HTTP 202 with a job ID. This Bell circuit samples two correlated measurement bits.

REQUEST_ID=$(uuidgen) # Save this with the body; reuse both on retries.
RESPONSE=$(curl --fail-with-body -sS "$BASE/api/jobs/stim" \
  -H "Authorization: Bearer $QSIM_API_KEY" \
  -H "Idempotency-Key: $REQUEST_ID" \
  -H 'Content-Type: application/json' \
  -d '{"name":"Bell pair","circuit":"H 0\nCX 0 1\nM 0 1","shots":1000,"seed":42}')
JOB_ID=$(printf '%s' "$RESPONSE" | jq -r '.id')
printf '%s\n' "$RESPONSE"

2. Poll

Check the returned status every few seconds. States are QUEUED, LAUNCHING, RUNNING, then SUCCEEDED, FAILED, or CANCELLED. Failed jobs include an error.

curl --fail-with-body -sS "$BASE/api/jobs/$JOB_ID" \
  -H "Authorization: Bearer $QSIM_API_KEY" | jq

3. Download

A successful job provides a NumPy archive containing measurements, detectors, observables, and exp_vals. The job response also includes a summary with outcome counts and a sample preview.

# Download only after status is SUCCEEDED.
curl --fail -sS "$BASE/api/jobs/$JOB_ID/result" \
  -H "Authorization: Bearer $QSIM_API_KEY" -o result.npz

Cancel a job

Cancellation is recorded immediately. Compute teardown can wait for an in-flight provisioning call to finish.

curl --fail-with-body -sS -X POST "$BASE/api/jobs/$JOB_ID/cancel" \
  -H "Authorization: Bearer $QSIM_API_KEY"

Python client

Install httpx and numpy, set QSIM_API_KEY, and run:

import io
import os
import time
import uuid

import httpx
import numpy as np

with httpx.Client(
    base_url="https://simulation.example.invalid",
    headers={"Authorization": f"Bearer {os.environ['QSIM_API_KEY']}"},
    timeout=30,
) as client:
    request_id = str(uuid.uuid4())  # Persist this and the body for retries.
    response = client.post("/api/jobs/stim", headers={"Idempotency-Key": request_id}, json={
        "name": "Bell pair",
        "circuit": "H 0\nCX 0 1\nM 0 1",
        "shots": 1000,
        "seed": 42,
    })
    response.raise_for_status()
    job_id = response.json()["id"]
    deadline = time.monotonic() + 1500
    while True:
        response = client.get(f"/api/jobs/{job_id}")
        response.raise_for_status()
        job = response.json()
        if job["status"] == "SUCCEEDED":
            break
        if job["status"] in {"FAILED", "CANCELLED"}:
            raise RuntimeError(job["error"] or job["status"])
        if time.monotonic() > deadline:
            raise TimeoutError(f"Job {job_id} is still tracked by wqsim")
        time.sleep(5)

    response = client.get(f"/api/jobs/{job_id}/result")
    response.raise_for_status()
    with np.load(io.BytesIO(response.content), allow_pickle=False) as result:
        print(result["measurements"][:10])

    # To cancel a pending or running job instead:
    # response = client.post(f"/api/jobs/{job_id}/cancel")
    # response.raise_for_status()

A client timeout does not cancel the server-side job. Save its ID to resume polling or request cancellation.

Learn to write a circuit request

A request has two parts: a circuit describing the quantum operations, and JSON fields specifying the result you want. Choose sampling for repeated measurement outcomes, or a probability query for exact probabilities of selected basis states.

The format endpoints take JSON and require your Authorization: Bearer … header and a saved Idempotency-Key. Use the quick-start submission and polling steps with any request body below. A 202 response means the job was accepted; circuit compilation errors appear later in its job status.

Stim: “What outcomes do I get when I measure?”

Start with qubit 0 in state |0⟩. H 0 applies a Hadamard gate, creating an equal superposition. M 0 measures that qubit. Stim uses numbered qubits and one instruction per line:

H 0
M 0

Send this JSON body to POST /api/jobs/stim. The \n represents a newline inside the JSON string; a Python client can pass a normal multiline string with json=.

{
  "name": "Sample one qubit",
  "circuit": "H 0\nM 0",
  "shots": 1000,
  "seed": 42
}

shots requests 1,000 repetitions, and seed sets the sampler’s random seed. Expect roughly half 0s and half 1s, not necessarily exactly 500 of each. The summary contains outcome counts; the downloaded NPZ contains individual measurements. Try removing H 0: all measurements should then be 0.

Learn the syntax in the Stim circuit-format guide ↗. For gates accepted by this engine, use Clifft’s supported-gate reference ↗. wqsim uses Clifft’s Stim-compatible input, including its extensions; the standalone Stim simulator has a different gate set.

OpenQASM 2: “What is the probability of each selected state?”

Declare a one-qubit register and rotate it by pi/3 about the Y axis. The header selects OpenQASM 2; qelib1.inc supplies standard gates. Each statement ends with a semicolon:

OPENQASM 2.0;
include "qelib1.inc";
qreg q[1];
ry(pi/3) q[0];

Send this JSON body to POST /api/jobs/qasm2:

{
  "name": "One-qubit rotation",
  "circuit": "OPENQASM 2.0; include \"qelib1.inc\"; qreg q[1]; ry(pi/3) q[0];",
  "bitstrings": [
    "0",
    "1"
  ],
  "bit_order": "big"
}

bitstrings specifies the states to query, in result order. This example returns probabilities approximately [0.75, 0.25], within floating-point precision. There are no shots or measurement instructions: the endpoint evaluates probabilities directly. Change the angle to pi to get approximately [0, 1]. For more qubits, each bitstring must match the register’s total qubit count; selected probabilities need not sum to 1 unless the selection covers the full distribution.

Learn the language from the OpenQASM 2 specification and examples ↗, then check Clifft’s OpenQASM 2 importer ↗ for the accepted subset. Clifft and the legacy Google qsim QASM2 probability path keep these restrictions: no classical registers, measurement, reset, conditions or custom gates. Google qsim QASM2 sampling and QASM3 add classical results and bounded custom gates; conditions remain unsupported. See each operation’s contract below.

This guide covers Clifft 0.11, Google qsim 0.22.1 and Qiskit Aer 0.17.2. Check authenticated GET /api/capabilities for your installation’s enabled operations. Upstream documentation may describe additional workflows; the endpoint reference below defines what this service exposes.

Stim sampling

POST /api/jobs/stim accepts circuit, optional name, shots (1–10,000), and seed. Put measurement instructions in the circuit. Results include measurement, detector, observable, and expectation-value arrays.

Run with Google’s qsim

Add "engine": "qsim" to an OpenQASM 2 probability request. Omit it or choose "clifft" to use Clifft. Google qsim runs on CPUs through the same job interface; status streams, idempotent retries, and NPZ downloads work the same way.

curl -sS "$BASE/api/jobs/qasm2" \
  -H "Authorization: Bearer $QSIM_API_KEY" \
  -H "Idempotency-Key: $(uuidgen)" \
  -H 'Content-Type: application/json' \
  -d '{"engine":"qsim","name":"qsim rotation","circuit":"OPENQASM 2.0; include \"qelib1.inc\"; qreg q[1]; ry(pi/3) q[0];","bitstrings":["0","1"]}'

Expected probabilities: approximately [0.75, 0.25]. Save the idempotency key before retrying a submission. The result summary identifies the engine and version. qsim uses single-precision arithmetic, so allow a numerical tolerance when comparing engines. It computes probabilities from amplitudes without shot noise; it does not promise bit-for-bit equality with Clifft.

Google qsim supports 1–26 declared qubits, including idle qubits. Registers follow declaration order and qubits follow numeric index order. The legacy QASM2 probability operation remains unitary-only, without classical registers or custom gates. The new sampling and QASM3 paths use Cirq 1.7.0 and the subsets below. See the qsim documentation ↗.

OpenQASM 2 basis probabilities

POST /api/jobs/qasm2 accepts circuit, optional name, required bitstrings (1–256 binary strings of equal length), optional engine (clifft by default, or qsim), and optional bit_order (big by default). Each string must match the circuit’s qubit count. For big, its first character maps to qubit 0; for little, its last character maps to qubit 0.

Clifft’s OpenQASM 2 importer supports unitary qelib1.inc circuits. Classical registers, measurements, reset, conditions, and custom gate definitions are not supported. This endpoint returns computed probabilities for the requested basis strings, without measurement sampling. Use Stim or explicit Google qsim QASM sampling for circuits with measurements. See Clifft’s supported input formats.

curl --fail-with-body -sS "$BASE/api/jobs/qasm2" \
  -H "Authorization: Bearer $QSIM_API_KEY" \
  -H "Idempotency-Key: $(uuidgen)" \
  -H 'Content-Type: application/json' \
  -d '{"name":"Bell probabilities","circuit":"OPENQASM 2.0; include \"qelib1.inc\"; qreg q[2]; h q[0]; cx q[0],q[1];","bitstrings":["00","01","10","11"],"bit_order":"big"}'

Save the idempotency key and request body before submitting; the example generates a fresh job. The completed summary reports probabilities [0.5, 0, 0, 0.5]. Its NPZ archive contains bitstrings and probabilities. Probability queries do not accept shots or seed on this endpoint.

OpenQASM 2 measurement sampling

Send the following JSON to POST /api/jobs/qasm2 with bearer authentication and a persisted Idempotency-Key. Select engine="qsim" and operation="sample" explicitly. This example writes qubit 0 into classical bit 1, producing counts {"010":128}.

{
  "engine": "qsim",
  "operation": "sample",
  "name": "Classical bit placement",
  "circuit": "OPENQASM 2.0; include \"qelib1.inc\"; qreg q[1]; creg c[3]; x q[0]; measure q[0] -> c[1];",
  "shots": 128,
  "seed": 42
}

Sampling supports terminal and mid-circuit measurement, reset, repeated writes and bounded custom gates. Classical bits start at zero; each shot starts fresh. A circuit must contain a measurement. Conditions remain unsupported, even when a branch would not execute. Sampling requests cannot include bitstrings or bit_order.

OpenQASM 3 and numeric bindings

POST /api/jobs/qasm3 requires an explicit operation. The binding examples here use engine="qsim"; see Aer for conditional sampling. The sampling example binds a custom gate and returns {"10":128}:

{
  "engine": "qsim",
  "operation": "sample",
  "name": "Bound custom gate",
  "circuit": "OPENQASM 3.0; include \"stdgates.inc\"; input angle[64] theta; gate turn(a) t { rx(a) t; } qubit[2] q; bit[2] c; turn(theta) q[0]; c = measure q;",
  "bindings": {
    "theta": 3.141592653589793
  },
  "shots": 128,
  "seed": 42
}

Bind exactly the declared input names using finite JSON numbers. Supported declarations are float[32], float[64], angle[32] and angle[64]. Widths do not promise width-specific arithmetic: values normalize to Python floats and qsim executes in single precision. Missing/extra names, strings, booleans, null and nonfinite values fail. Changing a binding requires a new idempotency key.

For selected basis probabilities, omit measurements and use operation="basis_probabilities". This request returns approximately [0.75,0.25] (absolute tolerance 1e-6 for this example):

{
  "engine": "qsim",
  "operation": "basis_probabilities",
  "name": "Bound rotation probabilities",
  "circuit": "OPENQASM 3.0; include \"stdgates.inc\"; input float[64] theta; qubit[1] q; ry(theta) q[0];",
  "bindings": {
    "theta": 1.0471975511965976
  },
  "bitstrings": [
    "0",
    "1"
  ],
  "bit_order": "big"
}

QASM3 probability requests support custom gates and unused classical declarations. Measurement, reset and conditions fail. Do not send shots or seed for probabilities. QASM2 does not accept a bindings object; its gate-local parameters must resolve from circuit expressions.

QASM3 bindings accept at most 256 entries, with names of 1–256 characters. Oversized mappings are rejected before a job is stored.

Read QASM sample results

The summary reports result_schema="qasm-samples/1". The NPZ contains classical_memory, a uint8 array shaped [shots,total_classical_bits]. Registers appear in declaration order, with ascending bit indices; summary.registers gives each name, size and offset. Count keys use this same left-to-right column order. Unwritten bits are zero; repeated writes retain the last value. Measurement-event history is not returned.

The complete artifact contains every shot. JSON shows at most the first 20 shots and 256 count entries, ordered by descending count with lexicographic ties. Each collection has a 512 KiB JSON budget and retains only complete rows or count keys. Check counts_truncated and preview_truncated; very wide registers can leave either collection empty.

Broader QASM subset limits

On Google qsim QASM2 sampling and QASM3 paths, includes are limited to packaged qelib1.inc and stdgates.inc. Conditions, unsupported control flow, file/network includes, executable Python and exponent expressions using ^ are rejected. Custom gates allow up to 65,536 expanded operations and nesting depth 32. Numeric literals must be finite with absolute value at most 1e100; resolved gate values must remain valid and finite. Clifft stays the default; unsupported requests never switch engines automatically.

Transactional submission and streaming

All three format endpoints require an Idempotency-Key: 1–128 ASCII letters, digits, dots, underscores, colons, or hyphens. Generate one per intended job and persist it with the request body. Repeating that key with the same normalized body under the same API identity returns the same job ID, even after a connection timeout or process restart. Changing the body with that key returns 409. Idempotency keys are scoped to each API identity.

Acceptance returns 202, a Location job URL, and Idempotency-Replayed: true or false. Acceptance means the job is durably queued, not that the circuit has compiled or succeeded. Retrying does not restart a failed or cancelled job; new work requires a new key. Reservations persist while the job exists and for at least 30 days from submission. During that window, retrying a deleted job returns 410. After reservation expiry, an old key may create new work.

Watch progress with server-sent events

curl -N --fail-with-body "$BASE/api/jobs/$JOB_ID/events" \
  -H "Authorization: Bearer $QSIM_API_KEY"

# After a disconnect, resume after the last fully processed event ID:
curl -N --fail-with-body "$BASE/api/jobs/$JOB_ID/events" \
  -H "Authorization: Bearer $QSIM_API_KEY" \
  -H "Last-Event-ID: 2"

Events have increasing per-job id values and JSON data. status reports queued, launching, and running states. result reports success with the final summary and authenticated result_url for the complete NPZ arrays. terminal reports failure or cancellation. A reconnect replays events after your cursor; no cursor replays all retained events. Save the ID only after processing the event, and deduplicate if your client retries processing.

Comments keep idle connections alive. Streams close at completion or after five minutes; a reconnect event requests reconnection with the same job and cursor. If a connection drops without that event, reconnect the same way. Disconnecting does not cancel or resubmit work. A revoked key closes the stream with an error event. Job deletion removes its event history. Each identity may open eight streams; the service allows 64 in total.

Incremental measurement samples are unavailable for all engines. Streaming provides durable progress and a final result summary, followed by a separate artifact download. The service does not split your simulation into independently seeded batches. GET /api/capabilities reports this limitation programmatically.

Classical conditions with Qiskit Aer

Select engine="aer" and operation="sample" on the QASM2 or QASM3 endpoint. Aer uses CPU statevector simulation in double precision. Check GET /api/capabilities for support on your installation. Jobs retain the same authentication, retries, status events and protected downloads.

QASM2 supports whole-register equality to an in-range integer followed by one standard gate statement. QASM3 supports scalar-bit equality to a boolean or whole-register equality to an integer, with flat if/else blocks containing gates, measurement and reset. For scalar QASM3 bits, use if(c==true), not an integer comparison.

Classical memory starts at zero. Conditions see the latest write, and a skipped measurement preserves the old value. Bit zero is the least significant bit in register comparisons. Results retain declaration-order registers and ascending bit indices in classical_memory. Each shot starts fresh.

QASM2 conditional gate

POST to /api/jobs/qasm2. Expected counts: {"1":128}.

{
  "engine": "aer",
  "operation": "sample",
  "name": "Conditional correction",
  "circuit": "OPENQASM 2.0; include \"qelib1.inc\"; qreg q[1]; creg c[1]; if(c==0) x q; measure q->c;",
  "shots": 128,
  "seed": 42
}

QASM3 branches

POST to /api/jobs/qasm3. Expected counts: {"1":128}.

{
  "engine": "aer",
  "operation": "sample",
  "name": "Conditional branches",
  "circuit": "OPENQASM 3.0; include \"stdgates.inc\"; qubit q; bit c; if(c==false) { x q; } else { reset q; } c=measure q;",
  "shots": 128,
  "seed": 42
}

Aer currently rejects probability queries, Stim, custom gate declarations, parameter bindings, nested conditions, loops, classical arithmetic, aliases, timing and external includes. Use finite numeric gate arguments and supported constant expressions; see the full gate and expression subset. Existing qsim custom gates and bindings remain available with explicit qsim selection.

Aer uses one native CPU thread, at most 26 declared qubits and the existing process memory limit. Both branches count toward operation and possible-measurement budgets. Samples arrive as a complete artifact; incremental sample streaming is not supported.

Execution & limits

Simulation execution is asynchronous. A submitted job may wait in the queue before it starts. Poll the returned job ID to follow progress.

  • Simulations run concurrently as cluster capacity permits. Placement failures stay queued and retry automatically.
  • Idle compute is reused with a fresh simulation process per job. Cold starts still add latency.
  • No elapsed-time or CPU-time deadline for active simulations. Explicit cancellation remains available. Idle workers are removed after work finishes.
  • Clifft: at most 4,096 qubits, active width 22, and 1,000,000 output cells.
  • Google qsim: 1–26 declared qubits, single precision, two CPU threads. All engines use the 2 CPU / 4 GiB worker profile and a 3 GiB process memory limit.
  • New QASM sampling: shots × (total classical bits + measurement events) cannot exceed 1,000,000 cells. Repeated writes consume event cells even though the artifact retains only final values.
  • No fixed saved-job count cap or active-job concurrency limit.
  • Completed jobs expire after 30 days. Download results you need to retain.

Clifft 0.11.0 provides CPU fixed-shot sampling and unitary basis-probability queries. Post-selection and experimental GPU backends are not exposed. Exact simulation still produces finite-shot statistical variation.
